# Эскиз PRO: UX и архитектура

## 1. Встраивание в РЕцепт PRO

Исходный репозиторий на момент начала разработки не содержал приложения или калькулятора — только один календарный файл. Поэтому инструмент реализован как самостоятельное клиентское web-приложение, не затрагивающее существующий функционал. Граница продукта намеренно проведена по сущности `SketchProject`: впоследствии приложение можно подключить как маршрут `/sketches/:id` в основном РЕцепт PRO или развернуть отдельно.

Для будущего backend API слой хранения изолирован в `src/storage.ts`. UI не зависит от IndexedDB напрямую: локальный адаптер можно заменить HTTP-репозиторием без изменения редактора.

## 2. UX-решение

### Основной сценарий

1. На стартовом экране пользователь загружает изображение или открывает недавний проект.
2. Изображение сразу открывается «по размеру экрана» и остаётся заблокированным фоном.
3. Частые инструменты доступны одной кнопкой на верхней панели и горячими клавишами.
4. Размер создаётся одним протягиванием; поле значения сразу доступно в инспекторе.
5. Объект двигается непосредственно на эскизе, редкие параметры меняются справа.
6. Автосохранение срабатывает через 1,6 секунды после изменения.
7. PNG/PDF экспортируются из верхней панели.

### Почему именно так

- **Фон нельзя случайно сдвинуть:** он не является выбираемым объектом. Панорамируется viewport, а не изображение.
- **Размеры не вычисляются из пикселей:** в модели хранится введённая строка `value`, геометрия служит только визуализацией.
- **Цепочка без диалогов:** первый клик ставит начало, каждый следующий создаёт сегмент; `Esc` завершает режим. Значения правятся последовательно в правой панели.
- **Мало модальных окон:** свойства находятся в постоянном инспекторе; после создания объект сразу выбран.
- **Большие изображения:** рабочая область прокручивается, поддерживает масштаб 10–300%, fit-to-screen и pan через пробел.
- **Повторяющиеся элементы:** `Ctrl/Cmd+D` создаёт смещённую копию.
- **Профессиональная безопасность:** undo/redo, автосохранение, раздельная видимость слоёв.

## 3. Модель данных

Проект — версионированный JSON-совместимый объект:

```ts
type SketchProject = {
  version: 1
  id: string
  title: string
  createdAt: string
  updatedAt: string
  image: { dataUrl: string; width: number; height: number; name: string }
  objects: SketchObject[]
  header: {
    enabled: boolean
    project: string
    room: string
    date: string
    variant: string
  }
  integration: { projectId?: string; clientId?: string }
}
```

Каждая аннотация имеет стабильный UUID, `type`, координаты в исходной системе изображения, цвет и размер текста. Типизированные варианты:

- `dimension`: две точки, ориентация, ручное значение, толщина;
- `module`: номер и многострочное описание;
- `comment`: текст;
- `callout`: точка объекта, позиция карточки, текст и опциональная ссылка;
- `equipment`: тип, подпись и URL модели;
- `link`: отображаемое название и URL.

Координаты не зависят от текущего масштаба. Это позволяет одинаково воспроизводить проект на разных экранах и при экспорте.

## 4. Рабочее поле

Выбран **SVG поверх неизменяемого raster-изображения**:

- SVG даёт резкие линии и текст при любом масштабе;
- каждый элемент остаётся отдельным интерактивным DOM-объектом;
- проще реализовать hit-testing, конечные маркеры и перемещение, чем на Canvas 2D;
- модель объектов не связана с SVG и позже может рендериться сервером;
- итоговая композиция растрируется только при экспорте.

Изображение и SVG используют одну координатную систему `0..naturalWidth × 0..naturalHeight`. CSS меняет только видимый масштаб.

## 5. Хранение

Для standalone MVP выбран **IndexedDB**: в отличие от `localStorage`, она подходит для крупных Data URL изображений и асинхронна. Проект сохраняется целиком, поэтому его можно открыть без исходного файла.

Для production-интеграции рекомендуется:

- изображение хранить в object storage (S3-совместимое), в проекте — `assetId`/URL;
- метаданные и объекты хранить как JSONB в основной БД;
- добавить optimistic concurrency (`revision`/ETag);
- периодически сохранять ревизии и аудит автора;
- оставить импорт/экспорт переносимого `.eskiz.json` как резервный формат.

## 6. Экспорт

- **PNG:** исходное изображение + SVG-аннотации + опциональная шапка компонуются в offscreen Canvas и сохраняются без изменения рабочего проекта.
- **PDF:** та же композиция размещается на A4 с сохранением пропорций; поверх известных координат URL добавляются PDF link annotations через jsPDF.

Для серверного production-экспорта можно использовать тот же JSON и headless Chromium. Это обеспечит воспроизводимость шрифтов и позволит формировать пакет документов независимо от браузера пользователя.

## 7. Будущая интеграция

Архитектурные точки расширения:

1. `integration.projectId/clientId` уже отделяют внутренний UUID эскиза от сущностей РЕцепт PRO.
2. Номера модулей — строки, поэтому могут принимать номера спецификации без миграции геометрии.
3. `storage.ts` — заменяемый repository adapter для REST/GraphQL API.
4. Техника хранит семантический тип и URL, а не только нарисованный текст; позднее можно добавить `catalogItemId`.
5. Заголовок хранится структурированно и может заполняться данными проекта/клиента.
6. Версия схемы позволяет выполнять миграции сохранённых проектов.
7. SVG renderer опирается только на модель, поэтому калькулятор может читать module IDs, не зная деталей интерфейса редактора.

Рекомендуемые будущие поля: `integration.sourceRevision`, `module.specificationItemId`, `equipment.catalogItemId`, `createdBy`, `revision`.

## Ограничения MVP

- хранение локальное и привязано к браузеру;
- совместная работа и серверная синхронизация отсутствуют;
- PDF использует растр для визуального слоя, но ссылки остаются интерактивными;
- цепочка создаёт сегменты с начальным значением 600 мм, значения вводятся вручную, как требует предметная область.
